# Setting up Docker locally

After you install the docker desktop, ensure that it is part of the path variable and available on the terminal as a command, you should get an output like below when checking for the version.
```shell {caption="Checking docker version."}
$ docker --version
Docker version 29.7.2, build a7dcaa6
```

## Setting up the container

These are the commands I used in the lecture to get the local setup going. The following command will pull the `sandbox` image and create the `lab` container on top of it.

```shell {caption="Creating a container using the sanbox image."}
docker run -it --name lab pyjamcafe/sandbox
```

If the `lab` container is not already running, use the following command to start it.
```shell {caption="Starting the container instance named lab."}
docker start lab
```

`attach` would enable us to connect to the container and use the shell available within it.
```shell {caption="Attaching to the running container."}
docker attach lab
```

# Docker and Codespace

`Docker` is an application available on Windows, Mac and Linux that lets us run a Linux Kernel based OS as a container. You can think of container as an isolation sandbox environment.

GitHub provides this very cool way of running a Docker image on a server. The original intention was that developer should be able to edit a GitHub hosted repo online.

The way it works is - When you go to a repo, and from the `Code` button and Click the `Create codespace on main`. The GitHub backend understands that you would like to edit that repo.

It spins a virtual machine which is running a default version of Linux and clones the git you create this codespace on.

Since the goal was to edit the files in the repo, the codespace is exposed in the browser as a VS Code instance in the browser. If you open the `terminal`, it allows access to the shell running on that virtual machine (a.k.a codespace!).

The terminal is what we care about as part of this course!

As you can imagine, there is a way to configure which Docker image will be used when creating the codespace. And, guess what? We have configured it to use the Docker image we created :)
